# NEUREQ Phase 1a: LLM-Driven Eligibility Question Modelling

## Overview
`neureq_ph1a.py` executes the first phase of the NEUREQ clinical trial evaluation pipeline. Its primary responsibility is to leverage a large language model (`DeepSeek-R1-Distill-Qwen-32B`) to evaluate the compatibility between a patient description and a clinical trial. 

Rather than outputting a single opaque relevance score, this script prompts the LLM to generate explicit, structured answers (YES/NO/NA) and natural-language justifications across a predefined schema of ten clinical eligibility questions. This structured output is crucial for both transparency and as the input representation for the downstream neural re-ranker in Phase 2.

## Technical Architecture
* **Model:** DeepSeek-R1-Distill-Qwen-32B
* **Precision:** 16-bit Float (FP16) via `bitsandbytes`. (Chosen to balance the large parameter count against GPU memory constraints without utilizing aggressive 4/8-bit quantization that might degrade clinical reasoning capabilities).
* **Hardware:** Hardcoded to execute on GPU index `1`.
* **State Management:** Implements an interrupt-safe execution loop. Progress is tracked via a `.json` file, allowing the script to seamlessly resume large-scale batch processing upon hardware or runtime failures.

## File Dependencies

### Inputs
1. **`prompt.txt`**: The static instruction prompt instructing the LLM on its role, the 10 specific eligibility questions, and the strict JSON output schema required.
2. **`ct_2021_queries.tsv`**: The patient case descriptions (queries) in tabular format (`qid \t query_text`).
3. **`corpus.jsonl`**: The total pool of 448,528 clinical trial documents formatted as JSON lines.
4. **`WholeQ_RM3_RETREIVAL_T2021.txt`**: The initial candidate list retrieved by the first-stage classical retrieval method (e.g., BM25+RM3). Defines which specific Patient-Trial (Query-Document) pairs need to be evaluated.

### Outputs
1. **`[RUN_FILE]_llm_responses.jsonl`**: The primary output artifact. A JSON Lines file where each row contains:
    * `qid`: Patient query ID.
    * `docid`: Clinical trial document ID.
    * `result`: The raw, unedited string generated by the LLM (including chain-of-thought traces).
    * `cleaned_output`: The sanitized, parsed JSON dictionary containing the 10 categorical responses and text justifications.
2. **`track.json`**: An integer state file retaining the index of the last successfully processed pair.

## Core Logic & Data Flow

1. **Initialization:** The script loads the FP16 DeepSeek model and custom tokenizer into GPU memory.
2. **Data Amalgamation (`load_data`)**: The script reads the first-stage retrieval text file and maps the integer IDs to their corresponding full-text patient descriptions and clinical trial data. 
3. **Prompt Construction (`generate_response`)**: For every pair, the patient and trial text are injected into `prompt.txt`. 
4. **Inference**: The LLM evaluates the prompt. To accommodate complex clinical reasoning, a large `max_new_tokens` allowance (4096) is provided.
5. **Output Sanitization (`clean_generated_text`)**: Reasoning models often preface their final answers with internal "thought" blocks (e.g., `<think>...</think>`). This function acts as a strict parsing filter:
    * It splits and discards the thought blocks.
    * It isolates the JSON structure.
    * *Note for Audit:* It enforces a heuristic limit based exactly on 10 closing braces `}`, aligning with the 10-question NEUREQ schema. 
6. **I/O Operations**: Results are appended to disk iteratively, paired with a state update to `track.json`, ensuring no data loss in the event of an interruption.

## Usage
Ensure the required input directories and dataset files (`data/2021/...`, `data/clinicaltrials/...`) are present relative to the execution directory.

```bash
python neureq_ph1a.py
