
# NEUREQ – Data Documentation

This document describes the **data files, formats, and directory structure** expected by the NEUREQ pipeline.  
The repository does **not redistribute proprietary or licensed datasets**; users are expected to obtain the required data independently and place them in the appropriate directories.

---

## Overview of Data Usage in NEUREQ

NEUREQ uses data in **three distinct roles**:

1. **Evaluation data**  
   - Official TREC Clinical Trials Track queries and relevance judgments (2021, 2022)

2. **Inference-time retrieval data**  
   - First-stage retrieval runs (BM25 / BM25 + RM3)

3. **Training data**  
   - Synthetic patient–trial triplets for training the Phase 2 neural re-ranker

Each role is isolated in a dedicated subdirectory to prevent data leakage.

---

**Note:** Only core input datasets are committed to this repository. The full **ClinicalTrials.gov trial corpus is an external resource and is not generated by any code in this repository**; it is not included here due to its large size (>**1.8 GB**). Intermediate or generated files (e.g., LLM outputs, hard-negative logs, tracking files, trained models, and run files) are created during pipeline execution and are **not included by default**. Users must obtain the ClinicalTrials.gov corpus independently and make it in a required format as per the codes and then place it at data/clinicaltrials/corpus.jsonl before running Phase 1.

## 1. Clinical Trial Corpus (`clinicaltrials/`)

### `corpus.jsonl`
- **Description**: Full ClinicalTrials.gov trial corpus
- **Format**: JSON Lines
- **Fields**:
  ```json
  {
    "id": "<trial_id>",
    "contents": "<full trial text>"
  }
  ```
- **Size**: 448,528 trials
- **Usage**:
  - Phase 1 LLM inference (`NEUREQ_ph1a.py`)
  - Hard-negative mining (`create_hardNegative.py`)

---

### `synthetic_gold_queries.tsv`
- **Description**: Synthetic patient case descriptions
- **Format**: TSV
- **Columns**:
  ```
  <topic_id>    <query_text>
  ```
- **Usage**:
  - Training data construction
  - Hard-negative mining

---

### `synthetic_gold_qrels.txt`
- **Description**: Gold relevance judgments for synthetic queries
- **Format**: TREC qrels
- **Columns**:
  ```
  topic_id  0  trial_id  relevance
  ```
- **Usage**:
  - Identifying positive trials during training data generation

## 3. Training Data (`train/`)

### `triplet_syn_training_data_1196.csv`
- **Description:** Final training dataset for NEUREQ Phase 2 and RouteSAE. Replaces the legacy .csv approach by providing rich structural and textual data.

- **Rows:**
  - 1,196 positive patient–trial pairs
  - 1,196 negative patient–trial pairs

- **Format:** JSON Lines

- **Schema:**
Each row contains the identifiers, the binary label (positive or negative), and the nested output dictionary containing the 10 categorical responses and natural-language justifications required for the BiLSTM and ClinicalBERT embeddings.

  ```json
  {
    "topic_id": 125,
    "trial_id": "NCT02595697",
    "label": "positive",
    "output": {
      "1": {
        "response": "YES",
        "justification": "The patient is 28 months old..."
      },
      ...
      "10": {
        "response": "YES",
        "justification": "The trial's treatment directly targets..."
      }
    }
  }
  ```

### `triplet_syn.jsonl`
- **Description:** A text-only variant of the 1,196 synthetic dataset used exclusively for training the deep neural baselines (e.g., standard BERT and CT-BERT Cross-Encoders). Unlike the NEUREQ dataset above, this file contains the raw text of the patient cases and clinical trials, bypassing the LLM eligibility extraction step.

- **Rows:** 1,196 queries, each mapped to one positive and one negative trial.

- **Format:** JSON Lines

- **Schema:**

```json
{
  "topic_id": "125", 
  "topic": "28-month-old male toddler with a confirmed diagnosis of...", 
  "positive_trial_id": "NCT02595697", 
  "positive_trial": "Study Title: Communication Intervention for Toddlers...", 
  "negative_trial_id": "NCT03838016", 
  "negative_trial": "Study Title: Preventing Speech and Language Disorders..."
}
```

*Usage:* Ingested by train_Bert_ctBert.py to flatten the triplets into pairs and feed the concatenated text strings into the baseline transformers.
---

**Positive trial identification:**  
The positive (relevant) trial for each synthetic query was obtained from resources released by the **IELAB team**, which provide one clinically relevant trial per synthetic patient case. From an initial pool of approximately **20,000 synthetic queries**, we randomly sampled **1,200** instances for training. After filtering out cases with invalid or non-conforming LLM outputs, the final training dataset contains **1,196 positive and 1,196 negative patient–trial pairs**.

These training queries and trials are **disjoint from the TREC 2021 and 2022 evaluation topics**, ensuring **no data leakage**.

### `hard_negatives.jsonl`
- **Description**: Identified hard-negative trials
- **Format**: JSON Lines
- **Fields**:
  ```json
  {
    "topic_id": <id>,
    "query": "<patient description>",

  }
  ```
---

### `hard_negatives_with_llm.jsonl`
- **Description**: Hard negatives with full LLM responses retained
- **Usage**:
  - Debugging
  - Error analysis

---

### Tracking and Logs
- `selected_queries.txt` – Queries sampled for hard-negative mining
- `processed_queries.txt` – Queries already processed
- `skipped_responses.jsonl` – Invalid or malformed LLM outputs

These files enable **resumable and fault-tolerant data generation**.

---

## Data Integrity and Leakage Prevention

- Training data is **disjoint** from TREC 2021 and 2022 evaluation queries
- Synthetic queries are generated independently
- No evaluation trial appears in the training set

This ensures **no data leakage** between training and evaluation.
