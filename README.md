# NEUREQ  
**Neural Ranking of Clinical Trials Using LLM-Based Eligibility Questions**

---

## Overview

NEUREQ is a **two-phase neural re-ranking framework** for clinical trial retrieval that integrates **large language model (LLM)–driven eligibility reasoning** with a **neural sequence model over structured eligibility signals**. The framework is designed to improve both **retrieval effectiveness** and **interpretability** in patient–trial matching tasks.

Unlike conventional neural re-rankers that operate directly on raw text embeddings, NEUREQ introduces an **explicit, interpretable intermediate representation**: answers to a fixed set of **ten clinically motivated eligibility questions**, each accompanied by a natural-language justification generated by an LLM. These structured signals are then modeled using a neural architecture that captures interactions across eligibility dimensions.

NEUREQ is evaluated on the **TREC Clinical Trials Track 2021 and 2022** datasets and consistently outperforms strong lexical, neural, and LLM-based baselines.

---

## Key Contributions

- Two-phase ranking architecture:
  - **Phase 1**: LLM-based eligibility question answering with natural-language justifications  
  - **Phase 2**: Neural re-ranking using structured eligibility representations and justification embeddings  
- Explicit modeling of clinical eligibility dimensions  
- Integration of LLM-generated reasoning into neural ranking  
- Model-agnostic first-stage retrieval (BM25, BM25+RM3)  
- Attention-based sequence modeling over eligibility questions  
- Interpretable relevance signals suitable for clinical analysis

## Eligibility Question Schema

NEUREQ models clinical relevance using the following ten eligibility questions:

1. Age Eligibility  
2. Gender Eligibility  
3. Condition Relevance  
4. Diagnostic Findings Match  
5. Prior Treatment Consideration  
6. Inclusion / Exclusion Criteria  
7. Pathophysiologic Mechanism  
8. Functional Status  
9. Interest in Experimental Therapy  
10. Treatment Target Alignment  

Each question is answered using a ternary scheme:

- **YES** – Criterion satisfied  
- **NO** – Criterion not satisfied  
- **NA** – Insufficient or missing information  

Each answer is accompanied by a short natural-language justification generated by the LLM to support interpretability.

## Phase 2: Neural Re-Ranking Model

NEUREQ Phase 2 models eligibility information as a **sequence of question-level representations** rather than as independent scalar features.

### Input Representation

For each of the ten eligibility questions, the following components are constructed:

- **Question embedding**: Encodes the position and identity of the eligibility question  
- **Answer embedding**: Encodes the categorical response (YES / NO / NA)  
- **Justification embedding**: Encodes the LLM-generated justification using a frozen ClinicalBERT encoder (`emilyalsentzer/Bio_ClinicalBERT`)  

These components are concatenated to form a per-question representation.

### Sequence Modeling and Attention

The sequence of ten question representations is passed through a **bidirectional LSTM**, producing contextualized embeddings that capture dependencies across eligibility dimensions. A **Bahdanau-style additive attention mechanism** is applied to compute a weighted aggregation over questions, allowing the model to focus on the most decisive eligibility factors.

The resulting context vector is passed through a feedforward classifier to produce a relevance score.

The model outputs a **scalar relevance score (logit)**, which is used to rank candidate trials.

---

### Multi-Level Interpretability Framework 

NEUREQ goes beyond simple retrieval effectiveness by providing a robust, multi-level interpretability framework to explain its ranking decisions. This framework operates at two distinct levels: the neural re-ranker level and the foundational LLM level.  

1. **Feature-Level Attribution (Phase 2 BiLSTM)**
To understand which clinical eligibility questions drive the final relevance prediction, NEUREQ applies an Attention × Gradient attribution method.

By multiplying the additive attention weights by the absolute gradient magnitudes of the input features, we can quantify the exact influence of each of the 10 questions.

This reveals, for example, that explicit mismatch criteria (e.g., Inclusion/Exclusion) carry significantly more decision weight than general functional status.

2. **Mechanistic Interpretability (Phase 1 LLM)**
To understand how the Phase 1 LLM (DeepSeek-R1-Distill-Qwen-32B) internally reasons about clinical eligibility, we apply a Route Sparse Autoencoder (RouteSAE) to its hidden states.

- **RouteSAE Training & Inference:** We dynamically route the LLM's mid-layer semantic hidden states and project them into a sparse, high-dimensional dictionary, uncovering thousands of discrete latent features.

- **Discriminability Analysis:** We calculate which sparse features fire strongly for eligible trials (positive discriminability) vs. ineligible trials (negative discriminability).

- **Approximate Pruning-MaxAct:** To assign human-readable clinical labels to these mathematical features, we reconstruct the evaluation prompts for the highest-activating patient-trial pairs and heuristically extract the top 5 most informative sentences. This creates concise evidence snippets for manual clinical interpretation (e.g., mapping a latent feature to "Knee osteoarthritis imaging criteria").

## Training Data

Training data is constructed using synthetic patient queries released by the IELAB team. Each query is paired with:

- one clinically relevant (positive) trial, and  
- a BM25-ranked list of candidate trials  

From this data, we construct training triplets:


(query, positive trial, hard negative trial)


Hard negatives are selected from the BM25 ranking using LLM-based evaluation over a subset of eligibility questions, ensuring clinically meaningful mismatches.

**Note:** This hard negative construction procedure is introduced in this work and is not part of the original IELAB dataset.

## Inference Considerations

NEUREQ requires LLM inference to generate eligibility responses for each query–trial pair. This introduces additional computational cost compared to standard neural rerankers, but enables structured and interpretable reasoning-based ranking.
