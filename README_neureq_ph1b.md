# NEUREQ Phase 1b: Data Sanitization and Validation

## Overview
`neureq_ph1b.py` serves as the data sanitization layer for the NEUREQ pipeline. While Phase 1a handles the heavy lifting of prompting the LLM for clinical eligibility evaluations, generative models—particularly reasoning models like `DeepSeek-R1`—frequently produce chain-of-thought artifacts, conversational filler, or malformed JSON structures. 

This script strictly enforces structural compliance. It parses the raw generative text, isolates the actual data payload, and verifies that the output perfectly matches the 10-question eligibility schema (YES/NO/NA + justifications) required by the downstream Phase 2 neural re-ranker.

## Technical Architecture
* **Paradigm:** ETL (Extract, Transform, Load) style string manipulation and validation.
* **Heuristics:** Uses strict character-splitting logic (`<think>`, `{`, `}`) rather than complex regex, optimized specifically for the fixed 10-question format established in the project methodology.

## File Dependencies

### Inputs
1. **`[RUN_FILE]_llm_responses.jsonl`**: The raw output file generated directly by Phase 1a. Each line contains the patient query ID, the clinical trial document ID, and the raw, unedited generative string.

### Outputs
1. **`[RUN_FILE]_llm_responses_sanitized.jsonl`**: The cleaned dataset. Each entry contains:
    * `qid`: Patient query ID.
    * `docid`: Clinical trial document ID.
    * `cleaned_output`: A fully validated dictionary containing exactly 10 key-value pairs representing the eligibility answers. If the LLM failed to produce exactly 10 answers, this value is set to `null` (None), ensuring bad data is flagged before it hits the neural network.

## Core Logic & Data Flow

1. **Chain-of-Thought Stripping:** The script isolates the final answer by discarding any text preceding or enclosed within `</think>` tags, which are characteristic of the DeepSeek-R1 model family.
2. **Bracket Isolation:** The script programmatically locates the first opening brace `{` to mark the start of the JSON object. 
3. **Truncation:** Because the LLM is instructed to answer exactly 10 questions, the script relies on a structural heuristic: it counts exactly 11 closing braces `}` (one for each of the 10 nested answers, plus the global closing brace) and truncates the rest of the string. This prevents trailing conversational text (e.g., "I hope this helps!") from breaking the JSON decoder.
4. **Validation:** The isolated string is parsed into a Python dictionary. The script performs a critical check: `len(parsed) == 10`. If the LLM skipped a question or hallucinated an 11th question, the entry is rejected and logged.
5. **Data Minimization:** The script drops the bulky raw text from the final payload, outputting only the identifiers and the clean dictionary, optimizing the file for the Phase 2 training/inference loops.

## Usage
Ensure `INPUT_JSONL` is correctly pointed to the output generated by Phase 1a.

```bash
python neureq_ph1b.py
