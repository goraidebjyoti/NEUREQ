# Interpretability Layer: Approximate Pruning-MaxAct (`pruning_maxact_routesae.py`)

## Overview
This script executes the final qualitative phase of the NEUREQ mechanistic interpretability pipeline. Analyzing sparse autoencoder features requires linking latent activations back to the specific textual contexts that caused them to fire.

Because the underlying LLM (`DeepSeek-R1-Distill-Qwen-32B`) processes massive prompts (up to 4096 tokens), visually inspecting the entire text for every activation is impractical. This script implements an **Approximate Pruning-MaxAct** procedure: it ranks the highest-activating examples for a given feature, reconstructs the prompt, and heuristically extracts the top 5 most informative sentences (the "evidence span"). These concise snippets are exported as JSON files for manual review, allowing researchers to assign clear, human-understandable clinical labels (e.g., *"Knee osteoarthritis imaging criteria"*) to the latent math.

## Technical Methodology

1. **Feature Selection:** The script loads the global test-set discriminability rankings (`feature_summary.json`). It isolates a target set of features (e.g., top 50), ensuring a balance between features with highly positive discriminability ($D_j$)—which encode eligibility—and highly negative discriminability ($-D_j$)—which encode explicit clinical exclusions.
2. **Context Reconstruction:** For a selected feature, the script finds the Top 20 patient-trial pairs (`MaxAct`) from the sparse activation tensor (`all_z.pt`). It reconstructs the exact Phase 1 LLM evaluation prompt using the base patient queries and clinical trial texts.
3. **Approximate Pruning:** Rather than executing computationally heavy token-level gradient attribution, the script relies on clinical heuristics. It splits the reconstructed prompt into sentences and scores them based on the density of clinical keywords (e.g., "inclusion", "biomarker", "prior"). The 5 highest-scoring sentences are retained as the evidence span.
4. **Annotation Scaffolding:** Generates highly structured JSON reports for every analyzed feature, alongside a blank template file, streamlining the manual human-in-the-loop review process shown in Table 1 of the study.

## File Dependencies & Formats

### Inputs Required

1. **`all_z.pt`**: A PyTorch tensor of shape `(Total_Samples, SAE_Width)` containing the exact activation values of every sparse feature for every patient-trial pair.
2. **`feature_summary.json`**: A JSON object generated by `infer_routesae.py`. Must contain the arrays `"top_positive_feature_indices"` and `"top_negative_feature_indices"`.
3. **`sample_ids.json`**: A JSON array of dictionaries mapping tensor row indices back to metadata: `[{"topic_id": "...", "trial_id": "...", "label": 1}, ...]`.
4. **`ct_2022_queries.tsv`**: Tab-separated file containing the raw patient cases: `<topic_id>\t<query_text>`.
5. **`corpus.jsonl`**: JSON lines file where each line is a dictionary containing `"id"` and `"contents"` representing a trial.

### Outputs Generated

All artifacts are saved to `routesae_inference/[RUN_STEM]/pruning_maxact/`.

1. **`selected_features.json`**: A simple JSON list of the feature IDs that were processed (e.g., `[35011, 4292, 12654, ...]`).
2. **`feature_[ID].json`**: Dedicated evidence files for each analyzed feature.
    * **Format:**
      ```json
      {
        "feature_id": 35011,
        "num_examples": 20,
        "candidate_concept": "MANUAL_INTERPRETATION_REQUIRED",
        "top_examples": [
          {
            "rank": 1,
            "activation": 12.45,
            "topic_id": "15",
            "trial_id": "NCT01954940",
            "label": 1,
            "query_preview": "A 64-year-old male with...",
            "pruned_text": "Inclusion Criteria: Evidence of knee OA..."
          }
        ]
      }
      ```
3. **`feature_interpretations_template.json`**: A blank key-value store for researchers to fill out once they review the evidence spans.
    * **Format:**
      ```json
      {
        "35011": "",
        "4292": ""
      }
      ```

## Usage

Ensure the `INPUT FILES` constants at the top of the script point directly to the output directory of your `infer_routesae.py` run.

```bash
python pruning_maxact_routesae.py
