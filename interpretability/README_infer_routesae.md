# Interpretability Layer: RouteSAE Inference & Test-Set Analysis (`infer_routesae.py`)

## Overview
`infer_routesae.py` executes the inference phase of the NEUREQ mechanistic interpretability pipeline. While `train_routesae.py` is responsible for learning the dictionary of sparse clinical concepts, this script applies that trained model to unseen test data (e.g., the TREC 2022 retrieval run).

By tracking precisely which of the thousands of sparse latent features activate for each patient-trial pair, we map the LLM's opaque vector space to human-understandable clinical reasoning. This script generates the activation records required to calculate feature discriminability and extract the local text snippets used for the manual semantic interpretations shown in Section 3.3 and Figure 2 of the NEUREQ paper.

## Technical Architecture & Pipeline

1. **Test-Set Integration:** Loads the top 100 candidate trials retrieved for each test query. It dynamically maps these pairs to the TREC gold-standard relevance judgments (`qrels`). Missing judgments default to `0` (non-relevant).
2. **Context Reconstruction:** The script rebuilds the exact textual prompt used to generate the LLM justifications. *This is a strict mathematical requirement:* to understand why the LLM answered an eligibility question a certain way, we must extract the hidden state generated by the exact same text string it saw in Phase 1.
3. **Hidden State Extraction (Sequential):** A forward pass through the frozen `DeepSeek-R1-Distill-Qwen-32B` base model extracts the intermediate representations. To prevent CUDA Out-Of-Memory errors on the 32B model, sequences are processed sequentially (Batch Size = 1). The states from the designated middle routing layers (25% to 75% depth) at the final prompt token are extracted and cached to disk as `.pt` tensors.
4. **Sparse Projection (Batched):** The cached tensors are passed through the frozen RouteSAE model in batches. The internal `Router` identifies the most salient layer, and the `SharedTopKSAE` projects it into the sparse feature space, forcing exactly `K=64` concepts to fire out of the expanded dictionary.
5. **Feature Attribution Log:** For every patient-trial pair, the script identifies the top 20 most strongly activated features and writes them to a comprehensive, human-readable JSON log (`active_features.json`).
6. **Discriminability Analysis:** Calculates the global test-set Discriminability score ($D_j$) for each feature by subtracting the mean activation on non-relevant trials from the mean activation on relevant trials.

## File Dependencies

### Inputs
* **Trained SAE:** `routesae_outputs/train_1196/models/routesae_final.pt` (Must match the architecture hyperparameters defined in the script).
* **Test Data:** `WholeQ_RETRIEVAL_T2022.txt` (Retrieval output), `ct_2022_queries.tsv` (Queries), `corpus.jsonl` (Trials), and `ct_2022_qrels_mapped.txt` (Judgments).

### Outputs
*All artifacts are saved dynamically to `routesae_inference/[RUN_STEM]/`*
1. **`features/active_features.json`**: The core artifact for qualitative analysis. A JSON array mapping every patient-trial pair to its top 20 active sparse concepts and recording the chosen router layer.
2. **`features/all_z.pt`**: The raw, unadulterated $N \times M$ sparse activation tensor.
3. **`features/feature_summary.json`**: Contains the highest-scoring positively and negatively discriminative feature indices for the test set, alongside feature activation frequency and dead-feature counts.

## Usage
Modify the variables in the `INPUT FILES` section to point to your desired baseline retrieval run (e.g., swapping `WholeQ_RETRIEVAL_T2022.txt` for `WholeQ_RM3_RETRIEVAL_T2022.txt`).

```bash
python infer_routesae.py
